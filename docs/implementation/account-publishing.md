## What the screens do

Open `/study/#/account` to request and enter an email sign-in code, restore an account, save a display name/timezone and sign out. The account check verifies the token with Supabase Auth and checks its live session and current role in Postgres. Profile saving uses an expected revision; it does not yet save study progress.

Open `/admin` or `/study/#/editor` for publishing. A student or signed-out visitor cannot enter the private workspace. The owner can add source references, a sourced exam cycle and topics; create or preview a structured JSON draft; inspect its teaching text/options/key; record source/rights/answer/explanation attestations; publish, replace or withdraw a version. Text renders as text. Imports do not carry approval flags or overwrite existing content identities. The current structured import format is `EditorialImportSchema` in `packages/contracts/src/editorial.ts`; it does not import the original HTML bank automatically.

All editorial changes use the same strict HTTP/RPC contract. The database independently rechecks session/role and validates direct requests. Edits create immutable snapshots. A correction targets the currently published version and swaps the public metadata projection atomically. Withdrawal preserves historical snapshots and audit. Successful commands refresh the workspace; uncertain retries retain the same request identity. The public exam-route reader sees only published public summaries, and distinguishes unavailable from unpublished.
